# Blackout Planner

Локальний десктопний планувальник побутових задач за графіком електропостачання.
Python, PySide6, SQLite. Реєстрація та сервер не потрібні.

## Запуск

Потрібен Python 3.12 або новіший. Застосунок перевірено у Windows 11 на Python
3.13. Перевірка на реальному Linux та Python 3.12 ще попереду.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m blackout_planner
```

Після встановлення у Windows можна двічі натиснути `run.cmd`.

```bash
# Linux
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/python -m blackout_planner
```

Дані зберігаються в системному каталозі застосунку. Для ізольованого набору:
`python -m blackout_planner --data-dir ./local-data`. Типовий часовий пояс —
`Europe/Kyiv`. Повторний запуск відкриває наявне вікно; другий процес на тому
самому каталозі даних не працює.

## Графік і задачі

Концепція «Спокійний день» використовує теплу теракотову палітру. Світлу або
темну тему можна обрати в налаштуваннях; вибір зберігається між запусками.
Першим показується поточний стан із позначенням джерела, найближча зміна
живлення та рекомендована справа. Далі розташовані картки задач і короткий
розрахунок автономності, а нижче — детальний таймлайн. На вузьких вікнах
блоки стають у вертикальну послідовність. Довгі списки прокручуються.

Основна дія має теракотовий акцент. Відключення на шкалі доповнені штрихуванням,
а ручні закріплення — окремим позначенням. Конфлікти та поточні роботи
показуються вище інших задач. Команда «Я починаю» підтверджує дію користувача,
а не вмикає прилад. На конфліктній картці можна змінити дедлайн і перепланувати
цю саму задачу зі збереженням її історії.

Початковий розмір вікна визначається доступною робочою областю екрана з
урахуванням системного масштабування й панелі задач. На невеликих вікнах
навігація згортається до піктограм із підказками, кнопки й панелі переносяться,
довгий вміст і форми прокручуються. При перенесенні на менший монітор вікно
зменшується до його робочої області. Майстер і діалогові форми також
відкриваються в межах екрана.

Кнопка ліворуч від заголовка розгортає або згортає бічне меню. Ручний вибір
зберігається між запусками й не скидається при зміні розміру вікна. Логотип
відцентрований у бічній панелі; SVG іконки малюються для фактичної щільності
екрана, включно з дробовими масштабами 125% і 150%.

Майстер першого запуску має чотири кроки: графік, пристрої, початкові задачі,
сповіщення й автозапуск. Додавання пристрою не створює задачу без підтвердження.
Тижнева таблиця має крок 30 хвилин. Невідомі клітинки не вважаються гарантованим
живленням. Параметри шаблонів є прикладами й потребують уточнення.

У розділі «Мій день» можна перетягувати сегменти з кроком 5 хвилин.
Перевіряються графік, дедлайн, потужність, резерв і зайнятість пристрою.
Переміщення, що створює новий конфлікт, скасовується. Прийняті сегменти
закріплюються й позначаються жовтим. Закріплення знімається кнопкою на картці.
Розпочату задачу перед переміщенням потрібно призупинити.

Кнопка «Уточнити світло» задає фактичний стан для конкретного інтервалу.
Пізніше уточнення має перевагу на спільному проміжку. Після його кінця знову
діє тижневий шаблон. Уточнення переглядаються й видаляються на вкладці «Графік».
Поточне аварійне відключення призупиняє активні задачі й переплановує залишок;
для неперериваної роботи користувач вирішує, чи потрібен новий повний цикл.

## Резерв і автономність

На вкладці «Автономність» задаються ємність, заряд, мінімальний резерв,
вихідна потужність, ефективність та сумісні пристрої. Увімкніть використання
резерву й збережіть параметри, щоб враховувати його в розкладі.

Права колонка порівнює автономність для різних наборів навантажень, не змінюючи
задач. Нульове навантаження та перевищення потужності показуються окремо.
Мінімальний залишок енергії враховується в плануванні. Майбутнє підзаряджання
резерву не припускається. Непереривана робота переходить між мережею й резервом
лише після підтвердження можливості безперервного живлення.

Павербанк чи ноутбук у списку пристроїв є споживачем під час заряджання.
Їхнє додавання не робить їх джерелом для інших приладів.
Прогрес і витрата резерву оцінюються за підтвердженим початком, часом і
потужністю. Пауза зберігає прогрес і зменшує залишок резерву, щоб не використати
енергію повторно. Це оцінка, а не телеметрія. Заряд можна уточнити вручну.
Час сну не зараховується як підтверджена робота. Після перезапуску активні
задачі потребують уточнення прогресу.

## Нагадування й автозапуск

- Попередження про відключення за 30 і 10 хвилин із незавершеними задачами.
- Початок вікна живлення та план на найближчі три години.
- Конфлікти з переходом до задачі та перенесенням на завтра.
- Розрахункове завершення активної роботи з підтвердженням результату.

Графік не вимірює напругу. «Світло з’явилося» використовується після ручного
підтвердження. Після запуску/сну показується актуальний підсумок; минулі
попередження не надходять пачкою. Історія запобігає дублюванню після перезапуску.
Події й дії також доступні у вкладці «Сповіщення».

У Windows використовується системний транспорт Qt: клік відкриває план,
кнопки дій доступні у вкладці «Сповіщення». На Linux використовується
`notify-send`, якщо його встановлено; кнопки доступні за підтримки `--action`
і `--wait`. Запасний транспорт — трей. ОС може приховувати повідомлення.

Автозапуск вмикається в майстрі або налаштуваннях. Windows використовує HKCU Run,
Linux — каталог autostart у XDG_CONFIG_HOME або ~/.config. Передаються абсолютні
шляхи та `--background`. Якщо трей недоступний, вікно відкривається звичайно.
Тести не вмикають автозапуск у системі користувача.

Закриття вікна за наявності трея приховує застосунок. «Вихід» завершує процес.
Вимкнений комп’ютер, сон і завершений процес не доставляють нагадування.

## Алгоритми й експерименти

Базова евристика впорядковує задачі за пріоритетом, потім за дедлайном.
Розпочаті роботи й ручні закріплення враховуються першими. Крок — 1 хвилина,
горизонт — 7 днів. Різні пристрої можуть працювати паралельно в межах
потужності. Непереривана робота займає суцільний інтервал; заряджання та
переривані роботи можуть ділитися між вікнами. Невдала спроба призначення
звільняє всі пробні ресурси задачі.

У налаштуваннях доступна локальна DP оптимізація першого вікна. Вона максимізує
суму пріоритетів неперериваних задач із дедлайнами не раніше кінця вікна за
гарантовано послідовного виконання. Для резерву, ручних закріплень і можливих
паралельних навантажень залишається базова евристика. Глобальна оптимальність
загальної задачі не гарантується.

```powershell
.\.venv\Scripts\python.exe -m experiments.compare --output experiments/results --repeats 3
```

Виконано 48 сценаріїв із seed 20261115. У послідовному наборі DP призначила
162 задачі проти 110, сума пріоритетів — 594 проти 466. У побутовому наборі
з резервом застосовується однакова базова евристика. Усі плани пройшли
незалежну перевірку ресурсів і дедлайнів.
Результати: [звіт](experiments/results/report.md),
[CSV](experiments/results/comparison.csv), [JSON](experiments/results/summary.json).

## Експорт і резервні копії

У налаштуваннях доступні JSON і календар ICS. Кожен сегмент стає окремою подією
з часом UTC і стабільним UID. Це знімок, без автоматичної синхронізації.

Резервні копії використовують SQLite Backup API, включаючи підтверджені дані
з WAL. Перед відновленням перевіряються цілісність, модель і налаштування.
Перед транзакційною заміною поряд із робочою базою створюється страхова копія
`before-restore-*.sqlite3`. Помилкова копія не замінює поточні дані.
Відновлення не змінює реєстрацію автозапуску в ОС.

## Імпорт графіка

Приклад: [examples/week.csv](examples/week.csv).

| Поле | Значення |
| --- | --- |
| day | 0 — понеділок, …, 6 — неділя |
| start | HH:MM, кратний 30 хвилинам |
| end | HH:MM; 24:00 дозволено |
| power | 1 — є живлення, 0 — немає |

JSON містить масив об’єктів із такими самими полями. Інтервал з кінцем раніше
початку переходить на наступний день. Перетини й неповний тиждень відхиляються.
Довільні файли обленерго потребують перетворення до цього формату.

## Перевірки й структура

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check .
```

- domain.py — моделі, обмеження, евристика та DP.
- storage.py — SQLite, імпорт, резервні копії й відновлення.
- ui.py, panels.py — майстер, форми, таймлайн, автономність і журнал.
- appearance.py — світла й темна теракотові палітри та стилі компонентів.
- theme.py — векторні піктограми й логотип з підтримкою DPI.
- overview.py — визначення найближчої зміни живлення для огляду дня.
- responsive.py — розміри вікон за екраном, прокручувані сторінки й форми.
- progress.py, notifications.py, notifier.py — прогрес і нагадування.
- platform_services.py, instance.py — автозапуск і єдиний процес.
- calendar_export.py — iCalendar.
- experiments/ — сценарії, вимірювання й результати.
- tests/ — перевірки логіки, файлів, адаптерів та інтерфейсу.

Поза поточним обсягом: інсталятори, перевірка на реальному Linux,
переклади та автоматичне отримання графіків з мережі.
