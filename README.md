# Blackout Planner

Локальний десктопний застосунок для планування побутових задач за графіком
електропостачання. Дані зберігаються у SQLite; реєстрація та сервер не потрібні.

## Запуск

Потрібен Python 3.12 або новіший. Розробка першої версії перевірена на Python 3.13
у Windows; перевірка Linux та Python 3.12 ще попереду.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m blackout_planner
```

Після встановлення у Windows можна запускати застосунок подвійним кліком по `run.cmd`.

Linux:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/python -m blackout_planner
```

Для ізольованих даних можна передати `--data-dir ./local-data`.
Без цього параметра використовується каталог даних застосунку відповідної ОС.
Типовий часовий пояс — `Europe/Kyiv`.

## Перша версія

- Майстер першого запуску: графік, пристрої, початкові задачі та нагадування.
- Тижнева таблиця з кроком 30 хвилин і станами «є», «немає», «не задано».
- Імпорт повного тижня з JSON/CSV з перевіркою інтервалів і підтвердженням заміни.
- Шаблони та редагування пристроїв, окремі задачі з пріоритетом і дедлайном.
- Priority/EDF-планувальник з хвилинним кроком на горизонті 7 днів.
- Паралельне виконання в межах потужності мережі та фонового споживання.
- Поділ заряджання й перериваних робіт між доступними вікнами.
- Таймлайн поточного дня, пояснення конфліктів, початок, пауза, завершення,
  скасування та перенесення задачі на завтра.
- SQLite, робота в треї за його наявності, базові попередження перед відключенням.
- Експорт розрахованих сегментів і конфліктів у JSON.

Параметри шаблонів є прикладами та потребують перевірки за характеристиками
власних пристроїв. Накопичувач у списку пристроїв є споживачем під час заряджання,
а не автоматично доступним джерелом живлення для інших приладів.

Фактичний початок і завершення задачі підтверджує користувач. Тривалість активної
роботи обчислюється від підтвердженого початку до паузи; це оцінка, а не вимірювання
обладнання. Після перезапуску непідтверджений прогрес активної роботи потребує
уточнення. Сповіщення про електропостачання спираються на графік. Коли процес
завершено або комп’ютер спить, повідомлення не доставляються.

## Імпорт графіка

Приклад повного тижня: [examples/week.csv](examples/week.csv).
Поля CSV та об’єктів у JSON:

| Поле | Значення |
| --- | --- |
| `day` | 0 — понеділок, …, 6 — неділя |
| `start` | Початок у форматі HH:MM, кратний 30 хвилинам |
| `end` | Кінець у форматі HH:MM; 24:00 дозволено |
| `power` | 1 — є живлення, 0 — немає |

JSON містить масив об’єктів з такими самими полями. Інтервал з кінцем раніше
початку переходить на наступний день. Перетини та неповний тиждень відхиляються.
Підтримується цей визначений формат; автоматичне читання довільних вивантажень
обленерго та зіставлення сторонніх колонок ще не реалізовані.

## Перевірки

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check .
```

## Структура

- `domain.py` — моделі та алгоритм, без Qt і SQLite.
- `storage.py` — репозиторій SQLite та імпорт файлів.
- `ui.py` — форми, майстер, таймлайн, картки, трей і фоновий розрахунок.
- `app.py` — запуск і вибір каталогу даних.
- `tests/` — перевірки обмежень планування, сховища та інтерфейсу.

## Подальші етапи

1. Датовані винятки графіка, ручне підтвердження аварійного відключення.
2. Ручне переміщення і закріплення задач на таймлайні.
3. Резервний акумулятор, сумісні навантаження та екран автономності.
4. Автозапуск Windows/Linux, сповіщення з діями, відновлення після сну,
   збереження історії нагадувань і повідомлення про початок вікна живлення.
5. Динамічне програмування для окремого вікна й порівняльні експерименти.
6. Експорт ICS, резервні копії, світла тема та локалізація.
7. Збірки й функціональна перевірка на Windows і Linux.

Базова евристика не гарантує глобально оптимального розкладу. Вона не призначає
прострочені задачі та не допускає виходу за підтверджені вікна живлення.
